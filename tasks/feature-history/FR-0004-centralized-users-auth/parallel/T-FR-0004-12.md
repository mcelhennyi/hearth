# T-FR-0004-12 — Users plugin multi-user auth API

**Branch:** `feat/FR-0004-centralized-users-auth-T-FR-0004-12-multi-user-auth-api`
**Worktree:** `.worktrees/FR-0004-centralized-users-auth/T-FR-0004-12-multi-user-auth-api/`
**Date:** 2026-05-26

## Summary

Converted `hearth-users` from the old single `local` password model to a
multi-user local account model. Fresh setup now creates an opaque-id first admin
with a normalized username, display name, and `admin,user` roles. Login requires
username plus password and returns claims from the stored user row.

## TEST

Added failing coverage before implementation for:

- migration of the legacy `local` row to an enabled admin account;
- username/display-name setup requirements and normalized username uniqueness;
- first-admin setup with opaque ids;
- multi-user username/password login;
- disabled users failing login and existing-session verify;
- lockout behavior under username/password login;
- session, verify, Spark `session.current`, and audit records returning stored claims.

The optional bootstrap password file remains a compatibility path only when no
users exist. It creates `username = "local"`, `display_name = "Local user"`, and
`roles = ["admin", "user"]` so existing dev/operator bootstrap flows still work.

## DEV

Implemented additive SQLite migration for `username`, `disabled`, and
`last_login_at`, with legacy `local` rows promoted to admin/user and sessions
kept mapped to the existing user id. Sessions now join against enabled users, so
disabled accounts fail closed for `/api/session`, `/api/verify`, and Spark
`session.current`.
